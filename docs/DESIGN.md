# ChatGPT Remote 界面

队列贴在输入框上方。可用动作来自原生队列，包括引导、删除、编辑和暂停后继续。输入区为空且原生窗口正在提供停止操作时，发送键显示停止方块。有文字或附件时，同一按键用于发送或排队。

手机弹层共用悬浮底部外壳、标题和右侧关闭按钮。模型面板顶部直接显示思考档位和闪电开关。下方模型按名称的自然宽度排列，间距固定，居中选中并首尾循环。模型名从中间向两侧逐渐透明，透明边界对齐档位文字左沿和闪电图形右沿。操作状态和错误统一通过浮层展示，弹层打开时位于其上边界上方。附件加号直接调用浏览器选择器。项目的下一层在弹层内部展开。审批显示请求说明及原生动作。草稿和队列编辑回到输入框。

发送中的三个点、取回电脑草稿与撤销合并放在输入框外侧上方，使用小胶囊；三个点轻微跳动。只有电脑与手机内容不同时才显示紧凑草稿提示，默认收起正文，点「查看」展开，点「替换发送」明确替换。手机本次选取的图片显示缩略图，点开使用图片预览弹层；普通文件显示文件条。图片解码不受支持时提示格式限制。

手机与电脑浏览器均使用上下布局。对话页的弹层和通知按输入框边框对齐，使用细边框和底色。胶囊保持内容宽度，水平居中。输入框、胶囊、弹层、通知依次向上排列，每层相距 8px。输入法、输入框、胶囊或面板内容高度变化时重新计算，加载前后保持相同底边。

模型目录使用当前账号的完整模型名称核对原生条目，配置动作单独处理。具体模型的思考档位由账号启用配置与模型支持项取交集，并核对原生当前名称、数量与位置；不会通过试切收集名称。中文显示「轻度、中、高、极高、Max、Ultra」，具体数量随账号与模型变化。轨道、停靠点与滑块共用坐标，首末位置为 0% 和 100%。拖动只作本地预览，点「应用」后重新核对账号配置，串行提交并回读，结果不明时停止、不重试。账号配置未同步或处于组合默认模式时，保留当前只读轨道与电脑画面入口。

`model_catalog.py` 仅以 GET 读取当前已登录账号的档位设置和模型目录，不更新账号偏好、不刷新登录信息、不发起模型推理。校验访问令牌的账号标识与当前桌面状态一致；读取后再次核对，切换账号即失效。凭据只在内存中用于原服务认证，不进入手机响应、日志或构建产物。设置缓存 20 秒、能力缓存 120 秒，应用前强制重读设置；并行冷读取本机实测约 2.1 秒。

思考滑杆只显示当前档位名称，名称、5px 轨道与快速模式按钮同排。竖向实心滑块为 9×18px，拖动时加高至 22px，触摸区域至少 44px。轨道与滑块共用坐标，两端为 0%/100%；标签列宽固定，改名不移动轨道。拖动连续跟随、松手吸附，减少动态效果设置会关闭过渡。参考 [Radix Slider](https://www.radix-ui.com/primitives/docs/components/slider)、[React Aria Slider](https://react-aria.adobe.com/Slider) 的独立滑块、拖动预览与提交阶段，使用现有原生网页组件实现。

模型目录返回一次性选择引用及各模型的可选档位。用户预览另一个模型时，手机立即使用该模型的档位范围；点「应用」才合并提交目标模型、强度和快速模式。服务核对账号、对话和原始选择，先检查目标档位可用，再执行原生模型切换，等待模型确认后处理强度和快速模式。每次按键前重新发现控件，等待焦点就绪，按键后核对名称和位置，最后由强度控件确认完成。已执行而结果不明时不重放；仅明确尚未执行的失效控件允许重新定位同一项一次。出现权限确认时返回待处理状态，部分完成时说明已切换的模型。

历史消息中的本地图片与正文图片引用使用缩略图和预览弹层，普通附件保留文件条。本地文件引用显示名称、行号和文字预览。缺失文件显示无法读取；不把电脑路径当成手机可直接打开的网址。图片按需加载，预览与重复读取共用有容量上限的内存缓存。

画面帧仅更新画布，连接或操作状态变化时才更新其余界面；统计信息最多每秒刷新四次。支持时在异步位图路径解码，释放用过的位图；保留顺序处理增量画面。远程模式上限 20 FPS，电脑端用可中断的定时等待维持抓取节奏，保持原有分辨率、压缩质量和传输容量限制。

公开过程说明直接进入消息区，公开思考摘要与工具活动保持折叠。活动按原轮次及最近一条用户消息分段，插话后的新进度留在插话之后，原始消息顺序不被折叠分组改变。目录按真实来源排除内部审查任务，并保留当前窗口提供的原生入口。同一对话重连保留消息元素、展开状态和阅读位置。

电脑管理窗口与手机网页组成同一个产品。电脑保留原有外壳、字体层级、浅深配色、材质、开关和设置布局。手机首页参考用户最新提供的简洁单卡图：产品栏、设置、电脑卡和底部帮助，恢复偏好收进设置。当前名称保持 ChatGPT Remote / Rm。聊天页以消息、输入框和原生队列为主体，不增加底部标签栏或常驻说明。

桌面面板保持 312×458 逻辑像素与 16px 外壳圆角。手机弹层的高度由内容决定，上限按可视视口计算。电脑画面展开在对话下方，保留会话和输入区，可手动全屏。

首次配对从电脑卡片打开六码弹层。配对后可直接恢复上次对话或画面，也可在设置中改为先打开设备首页。弹层共用一层浏览器历史，支持遮罩、返回和 Esc。文字流在弹层后继续同步，画面在被弹层遮挡或浏览器退到后台时暂停。

对话标题入口使用 14px 圆角点击区和同一套 SVG 下箭头，触摸按压显示柔和底色。项目面板按项目直接分组并支持搜索，本地目录提供完整条目，展开与重复打开使用页面内缓存。

缓存项目的展开独立于发送和后台读取；空项目展开后显示空状态。同一电脑窗口的状态版本更新时保留目录和展开位置，在后台校对新目录；切换窗口或服务实例时重新读取。目录中的操作目标经过新状态校验后才执行，项目折叠本身只改变手机显示。

主页直接展示连接二维码、配对码、电脑名称、连接地址、当前窗口和已配对设备。窗口直接选择，设备管理在原行展开。版本信息放在更新页。每次展开通过通知图标标识向 Explorer 重新读取坐标，并按目标显示器的 DPI 定位。

每次展开托盘面板回到首页；离开设置、返回设置时收起外观展开项。外观包含配色和材质，导航与原地展开遵循系统的减少动画偏好。手机设置、项目列表和输入选项共用页面层级、返回与关闭规则。

联系与支持使用咨询、QQ 联系与打赏卡片的结构。更新页使用产品标识、当前版本、GitHub 项目、主操作和更新状态的结构，说明按需展开。

界面启动前预备，隐藏后保留。隐藏期间停止页面轮询并清除配对码，状态请求合并；设置写入串行处理，界面即时响应，较旧的读取不能覆盖新的选择。

`WindowsAgent/desktop_ui.py` 组装托盘面板。`python -B tools/build_review.py` 从同一套手机和桌面模板生成离线预览，使用模拟数据。

玻璃沿用 ChatGPTnx 的 HostBackdropBrush 与 CompositionRoundedRectangleGeometry 组合，背景本身按 16 像素半径裁剪。轻量 C++/WinRT 宿主由同一 UI 线程创建和释放；主窗口直接应用同半径的区域。系统关闭透明效果或使用高对比度时显示纯色。

Rm 沿用 32 单位网格、R10 底板和 2.8 单位圆头笔画。深色界面搭配白底、黑字和细灰边，浅色界面搭配 #171717 底板和白字。面板跟随应用配色，通知图标跟随 Windows 任务栏配色，网页 SVG 标识跟随浏览器配色。

WindowsAgent/assets/rm-mark.svg 是唯一图形源；运行 python -B WindowsAgent/desktop_icon.py 生成浅／深 SVG 与各九种尺寸的 ICO。desktop.ico 保留深色标准版本，供快捷方式和不支持主题切换的入口使用。

已识别的桌面对话优先从本机结构化历史读取，真实消息类型和轮次决定角色、正文与活动；思考只展示公开摘要。原始数据库使用只读连接。原生控件负责输入和发送，空输入通过编辑器的占位结构判断，文件附加等待输入焦点生效并通过独立状态查询确认，响应丢失只重读结果。

普通文字使用一次原生 Unicode 输入，换行采用编辑器的软换行，确认完整内容后才触发发送按钮。长文字优先粘贴，剪贴板失败且输入回调尚未执行时改用原生输入。用户点按发送时，同一对话输入框里与手机完全一致的内容可直接提交。前台焦点在输入前变化时恢复一次，并重新核对对话和编辑器内容。

网页 SVG favicon 随浏览器浅／深色切换，手机添加到桌面的 PNG 使用深色标准版本。用户消息右对齐，正式回答直接排版。过程说明、公开思考摘要和网页搜索按最近一条用户消息分组。折叠入口显示原生“用时”状态，箭头位于文字右侧，下方细分隔线连接正文。生成时展示过程，结束后收起，手动展开状态随增量更新保留。思考摘要降低字号和亮度，网页搜索使用独立标识。队列位于输入框上方，用户时间放在元信息栏，回复完成后可复制正文。活动与耗时按结构字段呈现。

## 1.1.1 输入与连接

设置和项目面板使用输入框的宽度及外圆角，并覆盖输入区。简短状态、回答及草稿入口为输入框上方 8px 的横向 28px 小胶囊，复杂提醒在顶栏下方。正常说明之间的工具操作默认折叠，摘要来自实际操作类型和图标；手动展开后保留选择。

文字通过绑定当前会话的 UIA ValuePattern 写入，确认正文后调用原生发送按钮。网页草稿按稳定线程标识保存，附件逐个附加以核对原生移除目标。已执行的发送和附件移除只回读核实，不重复执行。电脑名称在配对卡标题编辑，配对码与二维码共享 60 秒有效期。

## 1.1.3 电脑面板

面板为 312×458 逻辑像素，16px 外壳圆角。电脑名称、配对码和复制入口置于二维码右侧；窗口项和设备项共用图标、文字与操作列，文字左边线为 52px。设备名称与配对日期同行，四台设备在标准视口内完整排列。设备区自然延伸；屏幕工作区不足时通过整页滚动访问全部内容，重新打开回到顶部。

## 1.1.6 电脑面板

整体继续保持 312×458 逻辑像素和 16px 外圆角。主页配对卡固定为 130px 高，名称行占 32px，设备行保持 44px。电脑名称与设备名称在原位置编辑，确认和取消为 14px 图标；复制图标为 16px，点击区域与可见图形分别控制。刷新以轻量文字呈现。移除设备使用同一行中的明确确认，其他行保持位置。

编辑状态、二维码换码和行内移除确认前后，二维码、配对码、地址、窗口区和设备列表的坐标及尺寸逐项相等。输入与光标在二维码轮换时保留；保存失败在原输入区保留内容，并通过底部状态与字段标识说明错误。默认展示约三行设备，更多设备通过整页滚动访问；滚动条隐藏，滚轮、触控板和键盘滚动保留。

菜单的浮层材质独立于主面板的模糊根节点。玻璃模式使用半透着色和 24px 背景模糊，浅深色共享同一套材质变量；纯色、系统关闭透明效果或高对比度时使用可读的实色后备。透明度仅作用于材质，文字与图标保持完整不透明度。视觉验证使用独立背景和实际截图，不能以样式属性存在代替可读性检查。

材质和布局参考 [Fluent Material](https://fluent2.microsoft.design/material)、[Fluent Layout](https://fluent2.microsoft.design/layout)，具体密度按该固定尺寸的桌面工具调整。当前预览与验证在 `_wip/AUTO_20261109PanelPolish/`。

## 1.1.7 首页服务状态

停止、启动中、配对码准备中、运行、启动失败和重连共用同一组容器。配对卡维持 130px 高；右栏使用 32/14/36/32px 四行，分别放电脑名、连接说明、主操作及有效期。启动按钮为 88×28px，位于配对码所在的 36px 行；二维码与等待图标共用 100×100px 区域。地址栏始终占 36px，窗口行始终至少 44px，设备行保持 44px。启动失败只改变原位置的提示与按钮状态。

312×458 视口的停止与运行截图复现了原模板的设备区从 y247.5 移至 y301，共 53.5px；电脑名所在栏也从 y74.5 变为 y61。当前截图确认停止、启动中、准备配对、运行的八处元素几何数据相同；浅色、失败及重连亦相同。滚动条继续隐藏，内容仍可完整滚动。证据为 `_wip/AUTO_20261109HomeStates/transition-result.json` 和按阶段编号的 JPG。

电脑名称为可选择的普通文字，铅笔为独立 28px 点击区；图标悬停底色为 22px。复制配对码保留 32px 点击区、24px 可见悬停底色；两者的按钮本体均保持透明。静态设备行只在编辑或确认时呈现操作状态，普通悬停由菜单按钮承担。

## 1.2.0 电脑面板：墨白与控制中心

品牌为 **C 字环 + ChatGPT 绿点**。唯一图形源 `WindowsAgent/assets/rm-mark.svg` 为满幅 32×32 字形，描边 currentColor、绿点固定 #10A37F，不含圆角底板；`rm-mark-light.svg`（黑环）与 `rm-mark-dark.svg`（白环）由 `desktop_icon.py` 生成，分别用于浅色与深色背景。应用图标 `desktop.ico` 为“深色圆角底板 + 白色字形”的展示变体，由生成器合成；托盘 `desktop-light.ico` / `desktop-dark.ico` 为透明字形，覆盖 16/20/24/32/40/48/64/128/256。`render_mark.ps1` 是通用 WPF 渲染器（path/circle/rect）。任何场景不得把圆角预裁进源文件。

视觉语言“墨白”：纯黑白灰，卡片 14px 圆角、1px 发丝线，无投影；正文 12、标题 13、强调 15、页标题 16、配对码 26/28；交互控件 8px 圆角；唯一彩色为状态绿与品牌绿。设置页、对话浮层、弹层材质同步；玻璃模式沿用半透着色与 24px 模糊，并提供实色与高对比度后备。

首页“控制中心”自上而下：两行状态带（连接地址 + 当前窗口，42–46px）、配对海报（92px 二维码、26px 配对码、倒计时环与刷新）、设备区。设备区按数量分档：0 台一整块圆角虚框；1 台通栏主卡（图标 chip、名称、已配对天数与日期）；2 台上下通栏；3 台四宫格 + “添加设备”格；4 台四宫格；5 台以上保持四宫格尺寸整页滚动，滚动条隐藏。六种服务状态共用同一位次：运行、已停止、启动中、启动失败、重连中、已暂停；非运行状态二维码区变为主操作（启动服务 / 启动中 / 重试启动 / 重新连接），失败原因就近显示。

短提示统一沉底（距底部 10px），带底部功能区的页面（版本更新）自动上移到 42px；不再使用“不上不下”的中间位置。开机自启由状态快照携带计划任务状态并缓存，打开设置立即显示，不再出现“读取中”。

规范参考 [Fluent Material](https://fluent2.microsoft.design/material)、[Radix Slider](https://www.radix-ui.com/primitives/docs/components/slider) 的独立滑块与提交阶段；图标源文件规范按“满幅方形源、平台负责圆角”执行。


## 1.2.2–1.2.3 固定三槽位与图标变体

二维码区固定 161px，自上而下三槽：92×92 二维码（运行）或占位方块（其余状态）；34px 行放配对码与复制（运行）或主操作按钮（启动服务 / 启动中 / 重试启动 / 重新连接）；18px 行放倒计时与刷新（运行）或一行提示。实测运行、停止、启动中、失败、重连下设备区起点均为 y=298，状态切换不位移。主操作按钮高 34px、最小宽 150px，与配对码同高。

面板标题使用裸 `rm-mark.svg` 字形（currentColor：深色面板白环、浅色面板黑环）与 ChatGPT 绿点；应用图标是“深色圆角底板 + 白环”的展示变体，由生成器合成，源文件不预裁圆角。`rm-mark-light.svg`（黑环）与 `rm-mark-dark.svg`（白环）只差环的颜色，几何与绿点完全一致。


## 1.2.7 桌面交互稳定性

面板继续使用 312×458 逻辑像素与 16px 外圆角。首页标题栏高 46px，状态胶囊宽 70px，倒计时文字宽 48px；字体和数字变化不重新挤压相邻元素。功能图标使用独立 `.ui-icon` 样式，品牌图形保持自己的描边与填色，纯绿圆点不带外描边。

设备数量继续采用 0 台空卡、1 台主卡、2 台双行、3–4 台四宫格、5 台以上整页滚动的规则。双行与四宫格卡片高 74px，主卡覆盖双行总高度；确认、编辑、处理中和失败内容在同一卡片外框内切换。输入错误占用卡内预留行，电脑名称错误以就近浮层显示，均不推动正文。

首页分为名称、状态、连接、配对、设备几个更新区域。相同内容保留原有节点；配对码更新保留菜单、输入值与光标，仍有效的旧码在请求中保留，过期后隐藏。操作开始前使旧状态读取失效，防止删除后的旧设备或启动前的旧状态重新出现。恢复焦点须确认面板仍拥有窗口焦点，且用户没有选择其他控件。

多窗口选择使用独立选择框，状态带始终保持两行。添加设备会将配对区带入视口并聚焦可用操作；主区域支持键盘滚动，菜单与原位编辑支持 Escape。短提示继续沉底。

布局证据位于 `_wip/AUTO_20261110PanelStability/browser-verification.json`；168 个隔离渲染场景均通过。本机原生材质与其他 DPI 的观感不由隔离渲染结论替代。


## 1.2.8 图标与动效

桌面右上角设置入口直接复用 ChatGPTnx 1.7.3 的齿轮路径，使用 18×18 viewBox、19px 显示尺寸和 1.65px 描边。按钮外框和设置导航保持原有尺寸与行为。

托盘按 Windows `SystemUsesLightTheme` 选择图标，深色任务栏对应 `desktop-dark.ico` 白环，浅色任务栏对应 `desktop-light.ico` 黑环；主题消息到达时重新选择。面板标题按面板自身配色切换环色，绿点与几何始终相同。

面板展开使用 260ms 淡入与轻微上移，页面切换 220ms，菜单展开 170ms、收起 120ms，设备内容切换仅做 180ms 淡入以保持外框位置，设置分组展开 240ms、收起 180ms。中断和反向操作从当前状态继续，关闭动效会完成当前显隐状态；隐藏面板会取消排队的展开动画。

“设置 → 外观 → 界面动效”保存显式开关；未设定时跟随系统减少动画偏好，用户明确开启后以应用开关为准。浏览器逐帧验证记录在 `_wip/AUTO_20261110PanelStability/motion-browser-1.2.8.json`：展开、页面和菜单有连续过渡；关闭后直接切换；移除确认全程卡高 74px、位置不变。
